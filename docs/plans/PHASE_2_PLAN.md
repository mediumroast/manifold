## Objective
When this phase is complete, the base bundle (version unchanged until the owner decides, Open question 7) enforces its file-writing rules at the tool boundary where the client allows it and states plainly where it does not; every review leaves `docs/plans/REVIEW_PLAN_<N>.md`; the planner amends a plan from it; the coder works checkpoint by checkpoint; a written procedure (`REVIEW_CYCLE.md`) and a `coordinator` agent run that loop and check the ready conditions; breaches are recorded in a templated, harness-named record by a written procedure; review approval is stated once, in an `AGENTS.md` "Review process" section, with no rule that the people in the repository cannot meet; and a `HOWTO.md` explains the whole cycle; where no quality repository exists, the test side (`test-planner`, `test-coder`, and the reviewer's check of a test plan) reads the originating intent, looks for gaps before it reads the existing tests, asks the human what it cannot decide and leaves a failing check red ([INT-25][i25], CP8 and CP9). All of it exists for the `claude` and `copilot` flavors, built from one source.

18. **How does the reviewer's check of a test plan fit its review passes?** (INT-25 Open question 2; blocks T52.) The owner answered, in INT-25: "I need more details place them in the plan for review. This doesn't make sense to me as worded." The details, in plain terms:
    - **What the reviewer's passes are today.** When the reviewer reads a change, it sorts every finding under a named pass, and `docs/plans/REVIEW_PLAN_<N>.md` has one heading per pass. `reviewer.agent.md` ("Review passes") lists them: "1. **Bugs.**", "2. **Security.**", "3. **Compliance with the plan and intent.**", "4. **Tests.**" and "5. **Context files.**"; its "Built-in defaults" call this "the four below (bugs, security, compliance with the plan and intent, tests), plus the context-files check". The template headings are pinned by a test (`test_bundle.py`, near line 1480: `### Bugs` to `### Context files`).
    - **What "no new pass" means.** INT-21's Out of scope (line 159) says: "Changing the review passes or what counts as Important in the template, except where needed to add the document's fields." The words "No new pass" are this plan's and the reviewer text's own (Concern 3, T17, and the reviewer section "When the change is mostly documents or agent instructions"): for documents the reviewer applies the existing passes with a standard, and adds none. So the constraint is: the list of passes and the template headings stay as they are.
    - **Why it is a question.** INT-25 asks the reviewer to open a test plan and report the signs of a plan that only mirrors existing tests (no intent cited, every case pre-ticked, no gaps, no questions, a case with no source) and never to approve it. A test plan is not a diff, so it fits no pass by itself, and the obvious fix, a new pass, is what INT-21 left out.
    - **Option A (recommended): a named check inside an existing pass, "Tests".** The reviewer text gains one short section, "When the change includes a test plan", listing the signs; findings are reported under **Tests**, which already asks whether the evidence matches. Changes: `reviewer.agent.md` (one section), `test_bundle.py` (one new test pinning the section and the signs in both flavors). Unchanged: the passes, `REVIEW_PLAN_TEMPLATE.md`, its heading test, the guard's reviewer allowlist, the one-file rule. This is how T17 handled documents.
    - **Option B: a fifth pass, "Test-plan reflection".** Clearest to read, and the signs get their own heading. Changes: the pass list and the "Built-in defaults" sentence in `reviewer.agent.md`, a new heading in `REVIEW_PLAN_TEMPLATE.md`, the pinned heading test and probably the reviewer tests that count passes (changing them needs your approval, rule "Tests under fix"), and your decision to lift INT-21's out-of-scope line. More change, and it contradicts INT-21 as written.
    - **Option C: a separate reviewer mode for test plans** (like the `test-planner`'s local and scenario modes: the reviewer starts with a mode line and its input is a test plan, not a diff). Keeps the passes untouched but the reviewer writes exactly one file (`REVIEW_PLAN_<N>.md`, INT-21), which is named for a phase plan, so a test-plan review needs either a second file, which breaks that rule and means changing the guard's reviewer allowlist and its tests, or a section in the same file. The largest change; it needs its own amendment.
    - **Recommendation: A.** It is the smallest change, it follows the precedent you already approved for documents (T17), it leaves INT-21 true as written, and the list of signs sits in one place that the checker `tests/live/plan_check.py` (T46) also holds, so the text and the check cannot drift apart. If reviews later show that test-plan findings get lost under Tests, B can be done then, with your decision to lift the INT-21 line. If you do not answer, T52 stays blocked and nothing else in CP8 or CP9 waits for it. **Answer:** Option A
