Residual gaps, in the guard's own words (the module docstring of `bundles/base/hooks/guard.py` is the source):

- a script that writes when it is run from a file (`bash s.sh`, `bash < s.sh`, `source s.sh`) is not read;
- a command or a path built from a variable (`eval $CMD`, `sh -c "$CMD"`, `X=.manifold/guard-allow.json; cp a $X`);
- the scratch route reaches protected files: a snippet written with Write to `.manifold/scratch/` and run is not read, so it can write `.manifold/guard-allow.json` (a path exception) and the agent can then Edit its own definition; the control is the coordinator's listing of every entry in `.manifold/guard-allow.json` and its review of each `exception-used` log line against an entry a human granted;
- code is matched, not understood: `-c`/`--eval` code is refused when it names a protected path or an API on the list, so a path built from parts (`"op"+"en"`) or an API not on the list passes;
- git commands that rewrite files without naming them (`git stash`, `reset --hard`, `checkout`, `restore`, `merge`, `pull`, `rebase`, `cherry-pick`) are allowed, they are normal work;
- wrappers and stdin: `script -c`, `su -c` and `xargs` fed from standard input are not followed;
- Copilot output may carry the guard's partial output before the fallback deny JSON;
- kept refusals: `cd` into a protected directory, and `python3 .manifold/hooks/guard.py` typed by an agent (the client runs the hook);
- command substitution inside double quotes;
- `sed` with a `w` command (it cannot be told from text without parsing sed);
- other languages, editors and tools than the ones named in the shell rule (for example `dd of=`, `curl -o`, `wget -O`, `tar x`, `unzip`, `install`, `python3 -m json.tool in out` are allowed although they write files);
- a `cd` in an earlier call followed by a bare file name;
- worktrees: a checkout counts as part of the project's repository only when its `.git` proves it (a `.git` directory, or a `.git` file whose git directory sits in the common directory's `worktrees/` folder, holds `commondir` and points back at that `.git` file); a checkout of another repository, a forged or unreadable `.git`, or a path in no checkout is judged as a path outside the project and matches no allowlist; whoever can write inside the repository's own `.git` directory can forge that proof; `.manifold/guard-allow.json` and `.manifold/guard-log.jsonl` are always the project directory's own, never another checkout's, so every checkout that can be a project directory needs its own installed guard;
- tools the guard does not look at;
- clients and sessions the hook does not cover: the main session under per-agent hooks, plugin agents, and Copilot, where enforcement is unverified;
- Copilot agent identity is unverified, so the reviewer and coordinator allowlists may not apply there, while the protected files apply to every identity;
- root `AGENTS.md` and `CLAUDE.md` are not protected: the installer writes the managed rules block there, but the same files carry "Project commands" and the "Review process" section that agents edit routinely; a change to rule text stays visible in review and in the "Rule exceptions" comparison (owner decision, 2026-11-07).

Rejected, with reason (CP2a): `bash < s.sh` is treated like `bash s.sh`, the scratch-script route, so the script is not inspected; `if [ $x > 1 ]` stays refused because in `sh` and `bash` it is a real redirect.
